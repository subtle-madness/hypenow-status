# 하입나우 서비스 상태

공개 상태 페이지: https://status.hypenow.io

GitHub Actions가 5분마다 아래 주소에 바깥에서 접속해 정상 여부를 기록하고, 그 기록과 이슈를 읽어 완성된 정적 HTML을 만들어 GitHub Pages(`gh-pages` 브랜치, 매번 고아 커밋 1개로 덮어씀)에 올린다.
우리 서버(오라클)와 따로 돌기 때문에 서버가 통째로 죽어도 이 페이지는 열린다. 설정은 [`.upptimerc.yml`](.upptimerc.yml) 하나다.

| 표시 이름   | 점검 주소                         | 의미                                   |
| ----------- | --------------------------------- | -------------------------------------- |
| 웹사이트    | `https://www.hypenow.io`          | 화면이 열리는지                        |
| 서비스 서버 | `https://api.hypenow.io/health`   | 서버 프로그램이 살아 있는지(DB 미확인) |
| 데이터 조회 | `https://api.hypenow.io/v1/stats` | 서버에서 DB까지 읽히는지               |

## 운영 방법

- **장애 자동 감지**: 점검이 실패하면 2번 더 확인한 뒤 장애 이슈가 자동으로 열리고, 복구되면 자동으로 닫힌다.
  자동 이슈 제목은 영어(`🛑 서비스 서버 is down`)로 고정이라, 고객에게 보일 문구로 제목을 고쳐 둔다.
- **장애 공지 직접 올리기**: Issues → New issue → "장애 공지" 양식. 라벨 `status`가 붙어야 페이지에 뜬다.
  소식은 댓글로 이어 쓰고, 해결되면 이슈를 닫는다.
- **점검 예고**: "정기 점검 예정" 양식. 시각은 UTC로 쓴다.
- **화면 생성 구조**: Upptime 기본 화면(브라우저가 GitHub API를 부르는 방식, 같은 IP에서 시간당 60회 제한)은 쓰지 않는다.
  [`site.yml`](.github/workflows/site.yml)이 [`build-site.mjs`](.github/scripts/build-site.mjs)로 HTML을 미리 만들어 올리므로 방문자 수와 무관하게 제한이 없다.
  점검 기록·자동 장애 이슈 반영은 점검 워크플로 종료 직후, 공지 이슈·댓글은 1~2분 안에 반영된다(안전망으로 30분마다도 돈다).
  수동 갱신: Actions → Static Site CI → Run workflow.
- **고객용 문구**: 화면에는 설정 이름(웹사이트·서비스 서버·데이터 조회) 대신 slug별 고정 문구(`SERVICES`, `build-site.mjs`)를 쓴다.
  기능을 추가하면 이 맵에 이름·설명·증상·점검 문구를 넣어야 한다(없으면 설정 이름으로 만든 기본 문구가 나온다).
  문의 메일 주소는 `SUPPORT_EMAIL` 상수. 화면의 색·글꼴·로고는 하입나우 프론트와 같은 값을 쓰고,
  로고는 `.github/scripts/assets/`의 축소본을 페이지에 직접 싣는다(하입나우 서버가 멈춰도 보이도록).
- **장애 묶기·진행 단계**: 열린(또는 닫힌) 자동 장애 이슈의 시작 시각이 서로 15분 이내면 고객에겐 하나의 문제로 합쳐 보인다
  (api가 죽으면 data도 같이 죽기 때문). 팀원이 쓴 수동 장애는 묶지 않는다.
  진행 단계(확인 중 → 원인 파악 → 복구 중 → 해결)는 팀원 댓글 맨 앞의 `확인 중:` `원인 파악:` `복구 중:` `해결:` 접두어로 올리고(전각 콜론 가능),
  접두어는 화면에서 뗀다. 접두어 없는 댓글은 직전 단계를 유지, 이슈를 닫으면 해결.
- **페이지에 실리는 이슈**: 라벨 `status`/`maintenance`가 붙고, 작성자가 저장소 소유자·멤버·협업자이거나 Actions 봇인 것만 싣는다.
  **외부인이 연 이슈와 댓글은 라벨이 붙어도 싣지 않는다.** 자동 장애 이슈는 제목·본문을 고정 한국어 문구(위 `SERVICES`)로 바꿔 보여주고 봇 댓글은 싣지 않는다.
  로직 시험: `node --test .github/scripts/build-site.test.mjs`
- **5분 주기 한계**: GitHub 예약 실행은 바쁠 때 몇 분씩 밀릴 수 있다. 팀이 즉시 받는 알림은 기존 Discord 알림이 맡는다.
